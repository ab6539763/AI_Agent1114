## 2. 业务需求说明 (PRD)

### 业务背景
星辰智脑每天面对高价值客诉、普通咨询、垃圾广告三类混合工单，全部调用昂贵的旗舰大模型会导致算力成本失控，需要基于规则的流程路由与终端运营控制台。

### 核心痛点
- 所有工单无差别调用旗舰模型，成本居高不下。
- 缺乏批量处理与异常跳过（continue）/ 熔断中止（break）机制。
- 运维脚本每次只能跑一个功能，缺少统一命令行菜单入口。

### 迭代目标
- 精通 `if / elif / else` 多分支路由与卫语句降嵌套技巧。
- 掌握 `for`、`while`、`range`、`break`、`continue` 在批处理与交互菜单中的应用。
- 完成工单路由分发器、九九算力表、猜数字二分验证器与可测试命令行菜单。

### 验收标准
- [x] 能按金额、关键词与客户等级将工单准确路由至 L1/L2/L3 通道。
- [x] 支持批量工单扫描：遇空工单 `continue` 跳过，遇高危攻击 `break` 触发熔断。
- [x] CLI 菜单支持传入模拟命令序列自动执行并正常退出，pytest 全部通过。

### 非功能指标
- 禁止无限死循环，所有 `while` 循环必须具备明确退出条件或最大步数上限。
- CLI 模块兼顾真实终端交互与无阻塞自动化测试。

## 3. 架构设计与交付清单

今天的代码包含两个关键工程模式：
1. **规则路由与批处理熔断模式**（day03_ticket_router.py）：在遍历工单队列时，空文本或无效数据用 `continue` 静默跳过并计数；一旦监测到疑似 DDoS 或批量注入攻击特征，立刻触发 `break` 熔断整批任务并告警，保护下游大模型额度不被刷爆。
2. **可测试的 CLI 命令分发器模式**（day03_cli_menu.py）：初学者写命令行菜单习惯直接 `while True: cmd = input(...)`，这导致代码完全无法做单元测试。我们的架构方案是：把命令处理抽成 `run_menu_session(commands)`，支持传入指令序列（测试时传列表，人工使用时再接 `input()`），彻底解耦 I/O 与业务逻辑。

### 当日交付代码文件
- `src/day03_ticket_router.py`：步骤一：实现工单三级分流路由器与批处理熔断引擎
- `src/day03_cli_menu.py`：步骤二：实现猜数字沙盒、九九乘法表与可测试 CLI 控制台
