## 2. 业务需求说明 (PRD)

### 业务背景
HR 与行政部门需要一个离线可用的内部通讯录 CLI 系统，支持快速录入、修改、删除员工联系方式，并持久化保存到本地 JSON 文件，便于星辰智脑后续接入查人技能。

### 核心痛点
- 员工信息分散在多个 Excel 表格里，查询慢且容易重复录入同一工号。
- 命令行程序关闭后内存数据丢失，缺少本地 JSON 持久化机制。
- 第一周知识点零散，需要通过综合项目将数据结构、函数与 JSON 融会贯通。

### 迭代目标
- 完成第一周核心知识（类型/切片/流程/容器/JSON/函数）综合自测与复盘。
- 独立实现通讯录完整 CRUD、关键字模糊搜索（姓名/部门/标签）、JSON 加载与保存。
- 确保所有业务操作与异常边界通过自动化集成测试。

### 验收标准
- [x] 支持按工号防重添加、更新、删除、精确查询与关键词模糊搜索。
- [x] 重启后能从 JSON 文件完整恢复所有联系人数据，中文无转义乱码。
- [x] 内置第一周自测判分引擎可自动评估答题正确率。

### 非功能指标
- 采用函数式模块化拆分：存储层（JSON I/O）与业务 CRUD 层分离。
- 所有测试在隔离临时目录运行，零残留文件。

## 3. 架构设计与交付清单

这是学员交付的第一个完整状态持久化应用，我们提前演练标准的「三层轻量架构」：
1. **存储持久化层**（`load_contacts` / `save_contacts`）：负责 JSON 文件读写、首次运行文件不存在时返回空字典兜底。
2. **领域业务层**（`upsert_contact` / `delete_contact` / `search_contacts` / `dept_summary`）：以工号 `emp_id` 作为 dict 主键实现 O(1) 定位，支持跨姓名/部门/手机号模糊搜索。
3. **展示与周测评估层**（day07_week1_quiz.py）：把第一周易错考点写成可执行的自动化判分引擎，帮学员用代码验证自己的理解。

### 当日交付代码文件
- `src/day07_week1_quiz.py`：步骤一：实现第一周知识点自动化周测判分引擎
- `src/day07_contacts_app.py`：步骤二：实现星辰企业通讯录管理系统（CRUD + 模糊搜索 + JSON 持久化）
