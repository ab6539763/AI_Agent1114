## 2. 业务需求说明 (PRD)

### 业务背景
杭州星辰数科新员工入职高峰期，飞书通讯录与内部 AI 助手「星辰智脑」需要统一的员工数字名片格式，既能展示个人基本信息与技术标签，又要避免在群聊中直接暴露完整手机号。

### 核心痛点
- 新人开发环境五花八门，Python 版本不统一导致依赖冲突频发。
- 直接连海外 PyPI 源下载依赖极慢，经常超时中断。
- 手工复制粘贴自我介绍格式混乱，手机号明文发群存在隐私合规风险。

### 迭代目标
- 统一团队开发环境：Python 3.11+、VSCode、pip 清华/阿里云国内镜像源与 Git 基础配置。
- 掌握变量命名规范、int/float/str/bool 四大基础类型及类型转换。
- 实现星辰员工数字名片生成模块与环境健康检查脚本，支持手机号脱敏与格式化卡片输出。

### 验收标准
- [x] 能输出当前 Python 版本、平台信息与标准镜像源配置命令。
- [x] 员工数字名片包含姓名、部门、工号、脱敏手机号、入职天数与 AI 权限状态。
- [x] 单元测试 pytest 全部通过，代码符合 PEP 8 命名规范。

### 非功能指标
- 零外部第三方库依赖，纯 Python 3.11 标准库运行。
- 所有核心函数支持传参调用，不阻塞标准输入，便于 CI/CD 自动化测试。

## 3. 架构设计与交付清单

在企业级研发中，Day 1 的核心架构思维叫做「环境一致性与数据边界清晰」。很多初学者把业务脚本写成一坨全局 print 语句，既没法复用，也没法写自动化测试。在 STARMIND-001 中，我们采用「两层解耦设计」：
1. 环境诊断层（day01_env_check.py）：负责采集运行时 Python 版本、操作系统和推荐镜像源，确保开发机满足团队基线（Python >= 3.10）。
2. 业务名片层（day01_profile_card.py）：将「输入数据校验与类型标准化」「敏感信息脱敏」「名片文本渲染」拆分成纯函数。这样即使未来林产品要求把命令行名片改成网页端卡片或飞书机器人推送，我们只需要替换最外层的渲染函数，核心的校验与脱敏逻辑一行都不用动。

### 当日交付代码文件
- `src/day01_env_check.py`：步骤一：编写星辰智脑开发环境自检脚本
- `src/day01_profile_card.py`：步骤二：实现星辰员工数字名片生成器（含手机号脱敏与配额计算）
