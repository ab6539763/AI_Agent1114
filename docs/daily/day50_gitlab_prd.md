## 2. 业务需求说明 (PRD)

### 业务背景
星辰数科技术委员会将于今天下午组织阶段项目三「多 Agent 智能办公助手」正式结项答辩。评委组要求研发团队提供可一键复现的 5 大核心场景自动化演示与 SLA 基准报告，并针对首版编排代码中 `if/elif` 硬编码路由与横切逻辑耦合问题提交重构方案。

### 核心痛点
- 人工现场演示容易手忙脚乱，且缺乏客观的成功率、HITL 拦截准确率、注入拦截率与 P95 延迟量化指标。
- 首版编排器把 Guardrail、RBAC 鉴权、Trace 计费与专家分发耦合在同一个大函数里，新增第 4 位专家（如“数据分析专家”）时需修改核心主干，违背开闭原则（OCP）。
- 阶段结束如果不做架构沉淀复盘，很容易遗忘各组件之间的演进脉络，难以在真实面试和架构评审中体系化输出。

### 迭代目标
- 构建项目三答辩自动化演示与压测评估套件（`day50_defense_benchmark.py`），一键跑通 5 类核心场景并输出答辩 SLA 指标看板。
- 完成代码评审重构实战（`day50_refactor_registry.py`）：引入“插件化专家注册表（Registry）+ 责任链中间件（Trace -> Guardrail -> RBAC -> Dispatch）”，实现零修改主干扩展新专家。
- 沉淀第四阶段（Day 39 ~ 50）多 Agent 中台演进全景复盘与标准 10 分钟项目答辩话术框架。

### 验收标准
- [x] 答辩基准套件覆盖制度查询、日程预定、邮件 HITL 放行、超额报销 HITL 拒绝、Prompt 注入拦截 5 类场景，综合通过率 100%，P95 延迟 < 50ms。
- [x] 重构后的中间件管道能按 `Trace -> InputGuardrail -> RBAC -> SpecialistRegistry` 顺序执行，注册新专家无需修改任何编排器主干代码。
- [x] 未授权角色触发受限专家时在 RBAC 中间件精准拦截，所有单测本地 100% 通过。

### 非功能指标
- 重构后的中间件接口遵循统一协议，支持动态插拔与独立单元测试。
- 答辩报告输出结构化字典与可读 Markdown 摘要，可直接粘贴进 GitLab 结项 Issue。

## 3. 架构设计与交付清单

优秀的工程项目不仅要“跑得通”，更要“讲得清、测得准、改得动”。今天我们聚焦两个高阶工程主题：

1. **10 分钟高分技术答辩结构（评委最爱听的 4 段式）**：
   - **第 1 分钟（业务痛点与量化目标）**：直击多系统割裂与高危误操作风险，给出明确验收指标；
   - **第 2~5 分钟（核心架构与关键技术取舍）**：讲清为什么选 Supervisor + LangGraph 状态机而不是黑盒 AgentExecutor，为什么对邮件和 >5000 元报销做 SQLite Checkpointer + HITL 异步中断，以及应用层+引擎层双重护栏；
   - **第 6~8 分钟（自动化端到端演示 + SLA 看板）**：直接跑通 5 类典型场景并亮出通过率、拦截率、P95 延迟和 409 防重放测试；
   - **第 9~10 分钟（线上踩坑复盘与中台演进路线）**：坦诚展示首版 `if/elif` 耦合问题及今天的中间件重构方案，并给出接入 MCP 统一工具网关与 PostgreSQL 多副本的演进规划。
2. **代码评审重构：从紧耦合编排到“责任链中间件 + 插件注册表”**：
   - 把横切关注点（`TraceMiddleware` 计时埋点、`GuardrailMiddleware` 注入拦截与脱敏、`RBACMiddleware` 角色鉴权）抽象为可组合的洋葱模型中间件；
   - 把专家分发重构为 `SpecialistRegistry`（注册时声明路由匹配器、所需角色权限与处理函数），以后接入第 4 位 `TextToSQLAgent` 或第 5 位 `CodeReviewAgent` 时，只需调用 `registry.register(...)`，彻底遵循开闭原则（OCP）！
