## 2. 业务需求说明 (PRD)

### 业务背景
星辰智脑项目组进入密集迭代期，团队需要轻量级任务清单工具追踪每日待办，同时知识库导入文档时存在大量重复标签需要自动去重与比对。

### 核心痛点
- 纯散装变量无法动态管理不断增减的任务列表。
- 人工比对两份知识库文档标签集合极易遗漏。
- 直接遍历修改列表导致索引错位漏删元素。

### 迭代目标
- 掌握 list 的增删改查、排序、列表推导式与浅拷贝安全遍历。
- 理解 tuple 的不可变特性及多值解包（unpacking）用法。
- 熟练运用 set 的去重及交集（&）、并集（|）、差集（-）运算。

### 验收标准
- [x] 待办管理器支持添加任务、按编号标记完成、删除任务、按状态过滤及列表统计。
- [x] 标签分析器能准确计算两批文档标签的去重全集、公共标签、新增与移除标签。
- [x] pytest 单元测试全部通过，包含空列表与越界索引边界处理。

### 非功能指标
- 禁止在遍历原列表时直接 `remove()` 导致漏元素，采用列表推导式或安全拷贝。
- 使用 tuple 返回只读统计快照，防止调用方误改内部状态。

## 3. 架构设计与交付清单

在 STARMIND-004 中，我们把三种容器各自的优势发挥到极致：
1. **待办任务存储（day04_todo_manager.py）**：外层任务列表用 `list` 维持添加顺序；单条任务的状态快照用不可变 `tuple` `(task_id, title, done)` 表示——更新状态时生成新元组替换旧元素，杜绝意外原地修改引发的隐蔽 Bug。
2. **知识库标签引擎（day04_tag_analyzer.py）**：把原始带重复和脏空格的标签列表清洗后转入 `set`，利用集合代数运算（交集 `&`、并集 `|`、差集 `-`、对称差 `^`）一行算出版本差异，最终排序转回 `list` 输出稳定结果。

### 当日交付代码文件
- `src/day04_todo_manager.py`：步骤一：实现待办事项管理器核心引擎（list + tuple）
- `src/day04_tag_analyzer.py`：步骤二：实现知识库标签去重与差异分析器（set）
