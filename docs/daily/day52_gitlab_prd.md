## 2. 业务需求说明 (PRD)

### 业务背景
星辰数科准备微调专属客服模型，历史工单导出的原始数据存在大量重复问答、空白回复、包含客户手机号隐私以及非标准格式问题，无法直接用于 LLaMA-Factory 训练。

### 核心痛点
- 原始导出的工单包含重复刷屏、无意义回复（如'好的''收到'）和敏感手机号泄露风险。
- 不同训练框架对数据格式要求不一：单轮指令偏爱 Alpaca 格式，多轮对话偏爱 ShareGPT 格式。
- 人工编写 500 条覆盖全业务线的标准问答耗时超过 1 周，急需可控的 Self-Instruct 模板与种子扩增流水线。

### 迭代目标
- 实现支持 Alpaca 与 ShareGPT 双向转换及 Schema 校验的标准化工具。
- 实现多阶段清洗管道：隐私脱敏、长度/黑名单词过滤、精确指纹去重与 Jaccard 近重复过滤。
- 构建可离线确定性运行的星辰客服 500 条垂直领域语料合成脚本，并按 9:1 切分 train/eval 集。

### 验收标准
- [x] 清洗管道能自动剔除长度过短、含'作为一个AI'腔调、完全重复及高相似度近重复样本，并输出清洗漏斗统计。
- [x] 合成器稳定输出 >= 500 条不重复、结构合法的 Alpaca/ShareGPT 语料。
- [x] 脱敏过滤器确保合成与清洗后的数据集不包含真实 11 位手机号。

### 非功能指标
- 本地纯 Python 离线可复现（固定随机种子），单次清洗 500 条耗时 < 1 秒。

## 3. 架构设计与交付清单

高质量 SFT（监督微调）数据集的核心原则是 **多样性（Diversity）+ 高纯度（Quality）+ 格式一致性（Consistency）**，而不是盲目堆砌十万条垃圾数据（LIMA 论文早已证明 1000 条精选数据即可激发强大的指令遵循能力）。

我们的语料流水线采用经典的 **ELT + Funnel（清洗漏斗）** 架构：
1. **种子扩增层（Self-Instruct Generator）**：在真实生产中，我们会用 20~50 条金牌客服种子，让强模型（如 DeepSeek-V3 / Qwen-Max）按预设业务矩阵（产品线 × 故障类型 × 客户身份 × 情绪等级）做定向扩增；在本地无外部 Key 环境下，我们用结构化槽位组合 + 变体模板引擎实现 100% 确定性合成，保证 500 条语料语义独立、话术规范且自带结构化处理步骤。
2. **清洗漏斗层（CleaningPipeline）**：依次执行 5 道关卡：
   - Schema 完整性校验（非空字段、合法角色）
   - PII 隐私脱敏（正则替换手机号、邮箱、身份证号为占位符）
   - 质量与黑名单过滤（剔除过短回复、拒绝'作为AI语言模型'等机械味表达）
   - 精确去重（规范化文本后计算 SHA256 指纹）
   - 近似去重（基于字符 3-gram 的 Jaccard 相似度阈值 >= 0.85 剔除洗稿样本）
3. **格式适配与切分层**：支持一键导出 LLaMA-Factory 原生识别的 `alpaca` JSON 或 `sharegpt` JSONL，并按分层随机抽样切分 90% 训练集与 10% 验证集，防止验证集数据泄露。
